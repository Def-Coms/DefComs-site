# Собствена система за проследяване на посетители

Без Google, без външни услуги — всичко се пази в малка SQLite база на твоя хостинг.

## 1. Качване на файловете

Качи цялата папка `analytics/` в основната директория на сайта си (по FTP или през
файловия мениджър на хостинга), така че да имаш например:

```
public_html/
├── index.html
├── other-page.html
└── analytics/
    ├── config.php
    ├── db.php
    ├── track.php
    ├── stats.php
    └── data/
        └── .htaccess
```

Увери се, че папката `analytics/data/` е с права за запис (обикновено 755 или 775
е достатъчно за PHP да може да създаде и пише в `visits.db`).

## 2. Смяна на паролата (задължително!)

Достъпът до `stats.php` се автентикира с паролния хеш в `analytics/config.php` (`admin_password_hash`) — в кода не се съхранява парола в чист текст. За да зададеш или смениш парола:

1. Отвори конзола/SSH в хостинга (или локално, ако имаш PHP инсталиран) и изпълни:
   ```
   php -r "echo password_hash('твоята-нова-парола', PASSWORD_DEFAULT);"
   ```
2. Копирай резултата (дълъг низ, започващ с `$2y$` или `$2b$`).
3. Отвори `analytics/config.php` и постави резултата като стойност на
   `admin_password_hash`.
4. Смени и `salt` с произволен дълъг текст (само ти трябва да го знаеш).

Ако нямаш достъп до конзола, кажи ми желаната парола и ще ти генерирам хеша.

## 3. Добавяне на tracking код във всяка страница

Добави този код точно преди `</body>` във всяка HTML страница, която искаш да
проследяваш (смени пътя, ако `analytics/` не е в основната директория):

```html
<script>
(function () {
    var page = encodeURIComponent(location.pathname);
    var ref  = encodeURIComponent(document.referrer);
    var img  = new Image();
    img.src  = '/analytics/track.php?page=' + page + '&ref=' + ref;
})();
</script>
```

Ако сайтът е генериран от шаблон/layout файл, добави кода само там на едно
място — ще важи за всички страници автоматично.

## 4. Преглед на статистиката

Отвори в браузъра:

```
https://твоя-сайт.bg/analytics/stats.php
```

Ще видиш dashboard с:
- Прегледи и уникални посетители за днес, последните 7 дни, текущия месец и общо
- Графика по дни за последните 14 дни
- Топ 10 най-посещавани страници за последните 30 дни

## 5. Автоматично изчистване на базата на всеки 3 месеца

Файлът `analytics/cleanup.php` трие посещенията и funnel събитията, по-стари от 3 месеца, и
компресира базата данни (VACUUM), за да не расте безкрайно.

**Хостингът ти е JetHost (cPanel)** — те предлагат вграден раздел **Cron Jobs**
в cPanel, така че ще ползваш истински PHP през конзолата (не е нужен URL/token
вариант).

### Стъпки в cPanel на JetHost

1. Влез в cPanel (през клиентския си профил в JetHost → cPanel).
2. Намери и отвори **Cron Jobs** (обикновено в секция "Advanced").
3. В полето **Common Settings** избери **Once Per Day** (или задай ръчно
   `0 3 * * *`, за да се пуска всеки ден в 03:00 през нощта).
4. В полето **Command** въведи (замени `ТВОЕ_ПОТРЕБИТЕЛСКО_ИМЕ` с реалното —
   виждаш го горе вдясно в cPanel, а версията `ea-phpXX` с версията PHP,
   която ползваш за сайта, напр. `ea-php82`):
   ```
   /opt/cpanel/ea-phpXX/root/usr/bin/php /home/ТВОЕ_ПОТРЕБИТЕЛСКО_ИМЕ/public_html/analytics/cleanup.php
   ```
   Ако не си сигурен коя PHP версия ползваш, провери в cPanel → **MultiPHP
   Manager** — там пише коя версия е активна за домейна ти.
5. Кликни **Add New Cron Job**.

Скриптът и без това трие само записи над 3 месеца, така че ежедневното му
пускане е напълно безопасно — просто поддържа базата постоянно чиста, вместо
да чакаш точно 3 месеца.

Ако предпочиташ да се пуска буквално веднъж на 3 месеца (1-во число на
януари/април/юли/октомври в 03:00), в **Common Settings** избери **Custom**
и въведи:
```
Minute: 0
Hour: 3
Day: 1
Month: 1,4,7,10
Weekday: *
```

### Проверка, че работи

След първото изпълнение ще се появи файл `analytics/data/cleanup.log` с ред
като:
```
2026-07-31 03:00:01 - OK - изтрити записи: 128
```
Можеш да провериш това по FTP/File Manager по всяко време.

(Скриптът поддържа и извикване през URL с таен токен, ако някога сменяш
хостинга и новият доставчик няма PHP CLI за cron — просто кажи и ще ти дам
точната команда тогава.)
