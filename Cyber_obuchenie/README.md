## Възможности

### За служители

- 📚 **Път на обучение** в 4 нива — начално, средно, напреднало (по профили: разработка / сигурност / устройства), управленско
- 🚪 **Постепенно отключване** — модулите се появяват месец по месец спрямо датата на регистрация
- 🧭 **Пътища по отдели** — администраторът задава персонален път на модули за всеки отдел (ИТ, HR, финанси…)
- 📖 Четене на материали по раздели с проследяване на време, после тест
- ✅ **5 типа въпроси** — единичен избор, множествен избор, вярно/грешно, подреждане, съотнасяне
- 🔀 **Варианти на тестове** — всеки опит е разбъркан случайно поднабор от въпросите
- 🔁 Повтарящи се опити; взетият тест отключва следващия модул
- 🔔 **Push известия** в реално време + имейл напомняния за падежи (SMTP)
- 🎯 **Лична цел** — служителят задава дата за завършване с графика на падежите
- 🏅 **Сертификати** за всеки модул и за цялата програма — кодове `SCA-XXXX-XXXX-XXXX`, публична верификация, лого **DefComs**, печат/PDF, споделяне в LinkedIn/Facebook
- 📱 **PWA** — платформата се инсталира на телефона/десктопа и работи офлайн
- 👤 Профил, мои опити с преглед на отговорите, активност

### За администратор

- 🏢 **Множество организации** с пълна изолация на хора, опити и отчети
- 👥 Управление на хора: ръчно добавяне, CSV/Excel импорт, редактиране, спиране, временни пароли
- 🏷️ **Отдели** — каталог, преименуване с пропаганда към хората, изтриване
- 🗺️ **Пътища по отдели** — постоянен набор модули за отдел; получават ги и всички бъдещи служители
- 📦 **Масови назначения** — по хора или по отдел: ниво, профил, ръчни модули, общ падеж
- ⏰ **Падежи** — автоматични и ръчни; просрочията се виждат навсякъде
- ✉️ **Фишинг симулации** — HTML кампании с `{{name}}`/`{{link}}`, уникален токен на получател, tracking на отваряния/кликове/докладвания, визуален преглед преди изпращане
- 📰 Известия и **седмичен имейл отчет** до администраторите
- 📦 **SCORM 1.2** пакети за външни LMS (Moodle и др.)
- 🧩 Пълно редактиране на модули — 5 типа въпроси, подреждане, копиране
- 🚀 **Бързи бутони „Пусни"/„Спри"** + **планирано публикуване** (scheduler по дата)
- 🔍 Търсачка/филтри, масово публикуване по ниво, статистика по модул
- 📊 **Отчети с диаграми** — KPI, donut по състояние, разпределение на резултати, седмична активност, успеваемост по модули; всяка графика е самостоятелна за печат
- 📤 **Експорти** — CSV, Excel (4 листа), интерактивен HTML отчет, печат/PDF
- 💾 JSON backup/restore + **автоматичен backup на БД** на всеки 6 часа (14-дневно задържане)
- 👤 Детайлна страница за всеки служител — прогрес, опити, активност

## Технологичен стек

| Слой | Технология | Защо |
|------|-----------|-----|
| **Рантайм** | Node.js ≥ 24 | `node:sqlite` — вградена SQLite, без нативни зависимости |
| **Backend** | Express 4 | REST API, sessions, SSE известия |
| **База данни** | `node:sqlite` (SQLite) | Файлова БД `data/platform.db`, миграции с `ALTER TABLE` |
| **Frontend** | React 19 + Vite 6 | SPA, без външни UI библиотеки — собствени компоненти и CSS променливи |
| **Рутинг** | React Router 7 | `/`, `/learn`, `/test/:id`, `/results`, `/certificate`, `/admin/*`, `/verify/:code` |
| **Автентикация** | bcryptjs + httpOnly бисквитка `sid` | Сесии в БД, rate limiting на логин |
| **Имейли** | nodemailer | SMTP опционално; без `SMTP_HOST` се логват |
| **Експорти** | `xlsx`, CSV, самостоятелен HTML | Excel с 4 листа, интерактивен HTML отчет |
| **SCORM** | `jszip` | Генериране на SCORM 1.2 пакети |
| **Файлове** | `multer` | CSV/Excel импорт на хора |
| **PWA** | manifest + ръчен service worker | Инсталация, офлайн shell |

> Цялото потребителско съдържание е на **български**.

## Бърз старт

Изисква се **Node.js ≥ 24** (заради `node:sqlite`).

```bash
npm install
npm run dev
```

| | Адрес |
|---|---|
| Приложение (dev) | http://127.0.0.1:5173 |
| API | http://127.0.0.1:3001 |

`npm run dev` пуска едновременно сървъра (`node --watch`) и Vite dev сървъра с проксиране на `/api` към :3001.

### Полезни команди

```bash
npm run build              # production build на клиента → dist/
npm start                  # node server/index.js — API + статиката от dist/
node server/import-modules.js        # импорт на модулното съдържание (идемпотентен)
node server/import-partN.js          # импорт на конкретна партида модулі
```

## Съдържание и модулен формат

**148 модула** в база данни (публикувани + чернови) — вижте `ROADMAP.md` за актуалния статус. Целта е 2-годишна програма с ~1 нов модул на месец; новите се добавят като **чернови** и се публикуват след преглед.

Нива: `начален` · `среден` · `напреднал` (профили: `разработка`, `сигурност`, `устройства`) · `управленски`

Праг за успешно вземане: **70%** (начално), **80%** (останалите нива)

### Формат на модула

Всеки файл `server/content/partN.js` експортира масив с обекти:

```js
{
  title: 'Заглавие на модула',
  summary: 'Едно изречение за какво е модулът',
  threatFocus: 'Кратка категория (Фишинг, Мобилни заплахи...)',
  releaseLabel: 'Начално ниво',   // Начално|Средно|Напреднало|Управленско ниво
  icon: 'eye',                    // име от MODULE_ICONS в client/src/icons.jsx
  estimatedMinutes: 18,
  passScore: 70,                  // 70 начално, 80 останалите
  sections: [{ id, title, body }],       // 4 раздела, 40–8000 знака
  questions: [{
    type: 'single',              // single | multi | truefalse | order | match
    prompt: 'Текст на въпроса',
    options: ['А', 'Б', 'В', 'Г'],        // при match: лява страна
    correctIndex: 1,             // single/truefalse
    correctIndices: [0, 2],      // multi
    correctOrder: [2, 0, 1],     // order
    pairs: [{ left, right }],    // match — двойки
    explanation: 'Защо е така'
  }]
}
```

Правила:
- `releaseLabel` — точно една от четирите нива
- `icon` — само имена от `MODULE_ICONS`; празно е допустимо
- Стил: реални сценарии от българската бизнес среда, конкретни стъпки, без жаргон без обяснение
- Файловете се сортират по ниво в `server/content/index.js`

### Работен процес по съдържанието

1. Нов `server/content/partN.js` с модулите
2. Малък идемпотентен скрипт `server/import-partN.js` (по образец на съществуващите) — вмъква като **чернови** (`published = 0`), пропуска дубли по `title`
3. `node server/import-partN.js` → `recomputeMonthNumbers()` в края
4. Преглед и публикуване в **Админ → Модули** (може и планирано по дата)
5. Обновяване на `ROADMAP.md` — задължително

## API накратко

| Метод | Endpoint | Описание |
|-------|----------|----------|
| POST | `/api/auth/login` · `/api/auth/logout` | Вход/изход |
| GET | `/api/me` · `/api/me/path` · `/api/me/attempts` | Профил, път, опити |
| GET/POST | `/api/modules/:id[/read|/heartbeat|/attempts]` | Учебен поток и тестове |
| GET | `/api/admin/overview` · `/api/admin/attempts` | Данни за админ преглед |
| GET | `/api/verify/:code` | Публична верификация на сертификат |
| GET/POST/PATCH | `/api/admin/orgs[/:id]` | Организации |
| GET/POST/PATCH/DELETE | `/api/admin/users[/:id][/...]` | Хора, отдели, назначения, импорт |
| GET/POST/PUT/DELETE | `/api/admin/modules[/:id]` · `.../reorder` | Модули |
| GET/POST | `/api/admin/departments/:name/path` | Пътища по отдели |
| GET/POST | `/api/admin/phishing[...]` | Фишинг симулации |
| GET/POST | `/api/me/certificates` · `/api/admin/certificates` | Сертификати |
| GET | `/api/admin/export` · `/export/detailed` · `/reports/html` | Експорти |
| PUT | `/api/admin/settings` | Настройки на организацията |

Админ endpoint-ите приемат организацията през `X-Org-Id` хедър или `?org=` параметър.

## Променливи на средата

| Променлива | По подразбиране | Назначение |
|------------|------------------|------------|
| `PORT` | `3001` | Порт на API/сървъра |
| `HOST` | `127.0.0.1` | `0.0.0.0` при директен достъп отвън |
| `SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASS`/`SMTP_FROM`/`SMTP_SECURE` | — | SMTP за имейли; без `SMTP_HOST` се логват |

## PWA и офлайн

- `manifest.webmanifest` + икони 192/512 — платформата се **инсталира** от браузъра (Chrome/Edge/Android)
- `sw.js` — service worker (само в production build): кешира статиката, `/api/` заявките винаги минават към мрежата, офлайн fallback към `index.html`
- Изисква HTTPS при публичен достъп (localhost е изключение)

## Backup и възстановяване

- **Автоматично**: `VACUUM INTO` всеки 6 часа → `data/backups/platform-YYYY-MM-DD.db`, задържане 14 дни
- **Ръчно**: копирайте `data/platform.db` — това е цялата персистентност
- JSON backup/restore също е наличен в **Админ → Настройки**

## Познати ограничения

- Потребителите не се регистрират сами — акаунти създава само администраторът
- Месечното разпределение е „месец" от ~30 дни спрямо `created_at` — без календарно подравняване
- Сравнението на отдели е case-insensitive, но не е accent-insensitive за кирилица (вътрешно сравнение е в JS)
- Фишинг симулациите изискват SMTP за реално изпращане; без него имейлите се логват
